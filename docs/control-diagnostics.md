# 双 C6 控制链路诊断与回归（2026-11-17）

主板 COM8，副板 COM9，副板为 `../TinyGate-ZigbeeNode`。主板使用 ESP-IDF v6.1、
Zigbee 库 2.1.0、测试模式 `coexist-test`。测试保留网络数据，没有修改副板程序。
Wi-Fi 为信道 6 的 WPA2 网络，Zigbee 使用已有网络；本轮不运行 UDP 或 BLE。

## 发现的问题

按用户原参数（Wi-Fi 已连接、180 秒、每 10 秒控制）重测，17/17 成功，未直接复现原来的 13/17。
提高到每秒一次、300 秒后，复现两次 2 秒控制超时。

其中 request 252 的两板日志提供了完整证据，时间均为主板同一 run 的单调时钟：

| 时间 | 事件 |
| --- | --- |
| 237124ms | 主板提交 request 252，目标 On |
| 239127ms | 达到 2 秒截止；无 TX 确认、无 ZCL 响应、未观察到目标状态 |
| 239131ms | 旧测试程序丢弃 request 252，立即提交 request 253；旧请求尚未结束 |
| 240432ms | request 252 的 TX 确认成功；副板同期输出实际执行 On |
| 240454ms | 收到 request 252 的 ZCL 成功响应，TSN 251 |
| 240524ms | 收到副板 On 状态报告 |
| 240835ms | request 253 收齐确认、响应和状态，被旧程序计为成功 |

这证明存在约 3.3 秒才获得发送确认的长尾，不能将其解释为“执行成功却只是 Rust 丢了回调”。
它超过本轮 2 秒业务要求，仍应计为超时。两端串口证据不能进一步区分共存调度、空口重试、
路由或 SDK 内部排队各占多少时间，不能据此宣称 C 驱动或射频问题已全部排除。

另外，单元回归确认判定器存在独立缺陷：迟到的错误 TSN 响应会覆盖已经收到的有效响应，
导致无法完成判定。该缺陷有确定的主机复现，但未证明它造成了用户原始 3 次超时。

## 修复行为

- 保留 2 秒业务截止，不重写或放宽原测试标准。
- 超时只计一次，继续保留原 SDK 在途请求；新控制必须等待它收尾，避免旧、新请求重叠。
- 晚到的完整成功或失败分别计 `ctrl_late_ok` / `ctrl_late_fail`，不改写已经发生的超时。
- TX 已完成但业务响应不完整，等待到 10 秒后可收尾，计 `ctrl_drained`；这不算成功。
  10 秒仍无 TX 确认时保留请求、输出 `CTRL_BLOCKED`，不再提交控制，不假装取消了 SDK 请求。
- stop 或到期时仍在进行的正常请求计一次 unfinished，并保留其收尾过程；新 run 在收尾完成前拒绝启动。
- 通过小容量候选缓存处理“响应早于 TX 确认”，已知 TSN 后忽略不匹配响应，重复回调不反转已记录的结果。
- `CTRL_SEND` / `CTRL_EVT` / `CTRL_RESULT` 日志记录 request ID、TSN、原始状态和阶段。
  原始状态域随事件类型区分，发送确认失败与 ZCL 错误分别分析。

`ctrl_late_ok`、`ctrl_late_fail`、`ctrl_drained` 是超时后的分类，不能再与 `ctrl_timeout` 相加作为失败总数。
`ctrl_inflight` 表示仍有请求需要收尾，`ctrl_deadline_ms` 明示本轮截止。
成功延迟直方图仍只包含按时成功的控制，必须同时报告超时率和样本数。

## 双串口测试工具

新增 `tools/dual_run.py`，复用自动测试脚本，同时占用两块板各自的串口；
主板仍使用有限时长测试，副板读串口不发送控制或复位。

```powershell
python tools/dual_run.py --port COM8 --node-port COM9 --run 401 --seconds 180 --control 10 --wifi "YOUR_SSID|YOUR_PASSWORD" --output test-results/control401.jsonl
# Zigbee 单模对照：省略 --wifi，脚本会先关闭主板 Wi-Fi
python tools/dual_run.py --port COM8 --node-port COM9 --run 402 --seconds 180 --control 1 --output test-results/control402.jsonl
```

采集前退出其他串口监控器。结果文件独占创建，不覆盖旧数据。
普通计数保存在指定 JSONL，两板诊断日志默认保存在同名 `-dual.jsonl`，不记录连接命令或密码。
PC 时间只用于粗略对齐两块板日志；控制延迟使用主板的单调时钟。
双串口诊断工具在运行结束后有意多采集 5 秒，用于保存迟到回调，可用 `--drain-seconds` 调整至 0..30 秒。
它与普通 `auto_run.py` 收到结束快照即退出的行为不同。
